# Roblox UI Regions

用真实 Frame 表达系统禁放区与可用空间，再由项目安排业务内容。保留顶部空闲空间；不以整体下移、逐控件追加顶栏高度或机型坐标表代替区域划分。

## 接入

1. 阅读目标项目规则，确认 UI 模板唯一来源、现有缩放负责人、源码同步方式和 HUD 生命周期。
2. 将 [UiRegions.luau](assets/UiRegions.luau) 复制到项目允许的通用或项目 UI 模块位置。运行时只依赖项目内副本，不读取技能目录。通用模块不包含场景 ID、业务节点或固定设计分辨率。
3. 在 Studio Edit 中运行 [BuildRegionFrames.luau](assets/BuildRegionFrames.luau) 返回的构建函数，传入正式模板根 Frame。该工具只维护自己命名的区域节点；同名异类节点报错。不要在游戏启动时创建区域 Frame。
4. 克隆完整模板后调用 `Bind`，传入 Root 与实际缩放读取函数。若项目原生触控结构不同，提供 FindControls，并通过 Observe 订阅自定义控件和祖先的变化。先绑定再执行项目布局。
5. 通过 Changed 统一刷新布局。业务只使用有效区域；控件尚未就绪时显式处理，不伪造精确边界。区域重叠查询使用完整控件命中范围。
6. 销毁 HUD 时断开业务 Changed 连接并调用 Destroy。更新机制时同步维护资产模板和项目运行副本。

区域 Frame 的 Visible 只控制调试展示，RegionValid 表达区域是否有效。默认隐藏、不接收输入；可用区是不同用途的候选空间，不能把 DeviceContentFrame 或 BodyFrame 当作已扣除全部触控区的万能安全矩形。

所有设备共用同一份 PC 基准排版和现有根 UIScale。只随可用视口等比缩放；各组使用同一套区域容器锚定规则，不能按 PreferredInput 切换位置、尺寸、安全区模式、紧凑卡片、字号补偿、最小触控像素或窄屏重排。输入方式只影响交互和提示，可拖动控件与鼠标提示共用同一操作槽位。静态设计参数保存在唯一模板中，不维护 Desktop/Touch 两套布局属性或模板。禁放区提供统一容器边界，不作为移动端专用兼容补丁的入口。

实现与排查时读取 [接口与坐标](references/regions.md)。不复制其他项目的 HUD 布局到本项目，不自动发布共享包。

## 验收

检查顶部左右占用变化、设备安全边界、偏移根节点、不同缩放、触控祖先显隐、控件延迟出现或替换、输入切换与视口变化，并对比输入切换前后几何必须一致。验证边界相切不算重叠、零面积无效、重复构建无重复节点、销毁无残留通知。分别报告模板持久化、源码同步、静态检查和实际运行验证。
