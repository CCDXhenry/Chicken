# 音效时长校准与触发验收

## 先找到错位发生在哪一层

读取素材、处理记录、资产清单、Studio 模板和所有播放调用方，沿输入、预测、服务端结果、动画到达、文字反馈逐层追踪。

- 素材过长：对比有效起音、脉冲次数和动作间隔，不能只检查文件是否存在或 SoundId 非空。
- 触发不对：记录哪个条件通过后才允许播放；同一业务结果是否被预测特效、服务端通知和文字提示重复播出。
- 实例不对：核对模板 ID、PlaybackSpeed、Looped、音量和回池后的残留状态。
- 修改未生效：区分本地文件、Script Sync 编辑草稿、已提交 Source 与运行中的旧模块缓存。

## 裁切与可复现处理

- 优先从已授权原素材提取单次有效起音，裁掉前置静音、重复脉冲和多余尾音；需要保留音色时不要通过 PlaybackSpeed 压缩时长。
- 根据动作和节奏定目标。一次性高频音效通常应在下次动作前完成主体与收尾；持续武器、环境循环和刻意叠加的余响另行设计，不能机械套用同一上限。
- 原文件只备份一次并保留哈希；重复处理从原文件读取，不能反复解码、裁切已经压缩的成品。
- 以短时 RMS 等方式定位起音，保留少量提前量；加短淡入和淡出，检查编码后重新解码的峰值，必要时衰减留余量，不能把数字削波当作安全限制。
- 区分解码后的有效时长与 MP3 容器报告时长，允许有据可查的编码延迟或填充；不要按文件字节数推算秒数。
- 记录源文件与源哈希、裁切起止、目标与成品时长、包络参数、安全增益和成品哈希。相同输入及处理参数重复生成应稳定。

## 触发条件

| 事件 | 应依赖的条件 | 常见错误 |
| --- | --- | --- |
| 开火 | 装备、冷却、角色存活、输入与瞄准等已有条件通过 | 按下即播，合法空枪却无声 |
| 受击／击败 | 用户选定的预测命中或权威命中事件 | 一次命中同时播受击和击败，文字提示又补播 |
| 拾取 | 确认成功，按表现设计在落袋到达时反馈 | 请求、模型预留、空收集或容量拒绝时提前响 |
| 容量拒绝 | 结构化拒绝原因 | 匹配“超重”“不足”等本地化文案推断失败类型 |
| 升级成功 | 对应操作成功或对应等级状态变化 | 仅凭窗口 pending 和金币减少推断成功 |
| 落地 | 实际落地或业务明确的地面生成完成 | 预测击败时抢先播放，给直接落地生成强加延迟 |

- 保留用户选择的预测策略。即时预测可能与权威结果不同；不要为了修声音擅自重写网络协议或改成全部等待确认。
- 同一结果指定一个声音入口。需要结果关联时复用已有业务标识，不用显示文案推断；已有结构化原因足够时不新加协议。
- 动画或锚点缺失时，成功反馈可按既有约定兜底一次；中途退出和正常完成不能各响一次。
- 密集拾取的合并窗口只限制音频，不丢物品、不减少动画或数量提示。窗口按本地生命周期维护，初始化赋值，销毁后不得继续播放；阈值由项目节奏决定。

## 回归与听感

- 覆盖合法空枪、非致命／致命命中、前置条件拒绝、晚到反馈不重复、空收集、满筐、批量落袋、合并窗口内外、模型与锚点缺失、销毁及回池复用。
- 离线加载真实模块，替换引擎边界；Lune 等环境与 Studio 的调度可能不同。模拟无参 task.wait 的帧间隔，用有上限的完成等待验证异步结果，避免一次固定睡眠造成抖动。
- 试听单发、按真实冷却连发和批量到达组合，关注起音滞后、尾音叠加、刺耳与截断。仅生成试听文件时明确标为待听感验收。
- 不为修音效主动启动 Play。静态回归、云端审核通过和真实场景听感分别报告。
