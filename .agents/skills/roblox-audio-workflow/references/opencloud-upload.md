# 指定音效增量上传与回退

## 上传前

确认目标 Place/Universe 及 CreatorType、CreatorId，按实际归属使用 userId 或 groupId。归属 ID 和凭据环境变量由项目配置提供，禁止照抄示例群组。只读取密钥是否可用，不输出凭据。

先确定授权音效名称列表；普通音效修正不默认重传全套音频或 BGM。

## 内容变化判断

- 为成品计算 SHA-256。已有资产 ID 只代表曾上传过，不能作为永远跳过的依据。
- 成品哈希相同则复用资产；哈希变化才上传指定名称的新成品，并在成功后切换映射。
- 旧清单没有哈希时，有原素材哈希可建立旧版本基线并识别本次变化；无法确认基线时明确说明首次迁移的限制，不凭猜测批量重传。建立可信基线后保存哈希供后续比较。
- 验证缺失文件、重复执行、旧清单迁移、变化文件、指定范围隔离和失败保留映射。

## Open Cloud 请求

- 创建：`POST https://apis.roblox.com/assets/v1/assets`，按当前官方接口要求提供 Audio 元数据和音频文件。
- 异步轮询：`GET https://apis.roblox.com/assets/v1/operations/{operationId}`。规范化返回 path，避免遗漏或重复添加 `assets/v1/`。
- 使用有上限的轮询与退避。429、权限错误或审核失败时保留旧映射，报告具体阻碍，不无限重建资产或切换到空 ID。
- 上传完成不代表审核通过或运行端可加载；能查询时单独核对审核状态，未核对时明确说明。

## 清单与恢复

清单保留声音名称、资产 ID、文件名、文件大小、上传时间和成品哈希；旧映射加入历史，可关联处理记录中的原文件及源哈希。

- 每条成功后持久化，采用临时文件后原子替换，避免中途失败丢失已完成结果。
- 无效／损坏清单应停止，不能静默当成空清单并批量重复上传。
- 上传失败不覆盖原有效条目，命令返回非零；未选中条目保持不变。
- 部署前比对本地文件与清单哈希，避免拿已变更文件对应的旧 ID 部署。

项目工具的参数与示例命令应在项目规范维护；本参考不依赖某个用户机器的 Python 桥接路径。
