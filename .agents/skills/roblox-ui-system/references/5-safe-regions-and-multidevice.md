# 固定画布与多端统一禁放参考

## 日常 UI 制作：只用一张图

- 普通屏幕 UI 的完整根画布固定 `1920×1080`，居中；所有内容在该画布内排版。局部面板、列表项按内容使用 Offset 尺寸。
- 根 UIScale 仅使用 `min(屏幕宽/1920, 屏幕高/1080)`，不扩展逻辑尺寸。若项目 UIAdapter 的 `FullScreen` 会扩展根尺寸，使用只缩放的 `Center` 模式。
- 屏幕容器 `ScreenInsets=None`，背景与模态遮罩独立铺满真实视口。画布之外显示游戏场景；不同宽高比不重排控件。
- Studio Edit 预置 `ReplicatedStorage.UI.ScreenLayoutGuideFrame`：透明 `1920×1080` Frame，内部 `ReservedAreasFrame` 由静态红色矩形表示全部已测端禁放区并集。
- 设计时临时复制到业务画布下，`AnchorPoint=(0,0)`、`Position=(0,0)`、尺寸不变、不加第二层 UIScale。所有节点 `Active=false`，不包含按钮/滚动容器。
- 普通文字、按钮和关键内容避开红色块；背景与装饰可进入。红色块已经包含统一间距，不重复追加同一间距。
- 完成设计核对后移除临时副本，正式业务模板不携带参考层。客户端不绑定、不监听、不查询这张图。
- 公共参考只纳入左上系统区与原生跳跃键的多端并集；不预留底部横条、设备侧边、右上系统区或左下摇杆。原始安全边缘数据可留档，但不参与参考图合并；纯展示层保持输入穿透，仍需实际验证触控行为。明确独立的端操作 UI 可维护独立变体，不将这些适配规则扩散到普通 HUD。

## 首次建立／补充设备时的开发期采样

采样只在建立参考图或补充设备时执行，不是每个新 UI 的接入步骤。

1. 先落地最终固定画布和根缩放，再启动已获授权的 Studio 运行客户端。记录当前设备模拟设置，完成后恢复并停止本次测试。
2. 查询 Studio 实际预设 ID，覆盖桌面 1920×1080、1280×720、2560×1440、2560×1080；手机覆盖常规 16:9、超宽、刘海/切角；平板覆盖 4:3 与接近 16:10。手机、平板采集两个横屏方向。
3. 布局稳定后读取真实屏幕尺寸、根原点、根缩放、逻辑尺寸、设备四边安全区、顶栏左右系统占用区、有效可见跳跃键；不采集摇杆。尺寸以客户端实际读数为准，不以预设值替代。
4. 普通系统按钮及收起聊天的布局纳入参考；展开聊天窗口、系统菜单和软键盘等临时覆盖层不永久预留。确保截图与测量状态对应。
5. 跳跃键只在自己和所有 GuiObject/ScreenGui 祖先均可见且尺寸非零时纳入。缺失、隐藏和读取失败分别记录，失败不能被当作无占用。
6. 保存原始 JSON 与截图，注明 Studio 模拟还是物理真机、设备预设、方向、时间、系统状态；不能将模拟结果描述为真机测试。截图工具若遗漏 CoreGui，补充应用窗口截图核对系统按钮。

采样资产 `ReadScreenLayoutSample.luau` 在**客户端插件上下文**执行；先配置该项目的 ScreenGui 和业务根路径。它不是业务脚本，不复制进 Scripts 同步根，不向游戏注入长期监听。

## 坐标换算与并集规则

`GuiService:GetInsetArea` 的原点与 GuiObject.AbsolutePosition 必须统一：

```text
full = GetInsetArea(ScreenInsets.None)
shift = -full.Min
屏幕矩形 = 引擎矩形 + shift
画布屏幕原点 = Root.AbsolutePosition + shift
设计矩形 = (屏幕矩形 - 画布屏幕原点) / 根缩放
```

- 先与 `[0,1920]×[0,1080]` 求交；完全位于画布外及零面积区域不纳入。
- 再向外增加默认 `24` 设计像素间距，向外取整并裁回画布。
- 通过 includedRegionNames 选择 TopLeftCore、JumpButton，其他原始矩形仅留档；对全部入选有效样本取精确矩形并集，分割后只合并相邻且边界匹配的矩形；保留不连续区域、顶部中央通道和内部空洞。不使用整组大包围盒。
- 工具必须验证：根逻辑尺寸、缩放、居中原点和遮罩尺寸正确；合并结果完整覆盖每一个已扩边矩形。
- 不给所有项目预填同一组矩形数值。各项目以自身最终缩放、系统设置及采样矩阵生成结果。

离线工具调用：

```text
python scripts/build_screen_layout_guide.py samples.json --output-dir output
```

输入包含 `canvas=[1920,1080]`、`padding=24`、`includedRegionNames=["TopLeftCore","JumpButton"]`、`samples`。每个样本包含 `logicalSize`、`screenSize`、`origin`、`scale`、`movementExcluded=true`、`modal.size`，以及 `reserved=[{name,screenRect:[x1,y1,x2,y2]}]`。采样器输出这些字段；设备标签和截图路径由采样执行器补充。

输出投影记录、`screen-layout-union.json` 和 `screen-layout-guide.svg`。在 Studio Edit 中执行构建资产，以 `BuildScreenLayoutGuide(UI文件夹, rectangles)` 创建或更新唯一公共模板。矩形数组为设计坐标 `[x1,y1,x2,y2]`。业务不依赖参考块数量与名称。

## 运行时与验收边界

- 客户端只有根整体缩放；普通 HUD 不使用区域控制器、顶栏水平夹取、设备分支或原生控件追踪。
- 顶栏／设备采样与离线并集不进入客户端。旧动态区域模块、区域节点和区域绑定 Attributes 在调用迁移后移除。
- 将参考图反投影到已测设备，并结合截图与数值验证覆盖；确认正式模板没有参考副本，背景/遮罩铺满视口。
- 验证 HUD 重复初始化、销毁、事件解绑与模态交互。独立端操作 UI 单独验证，不强制普通 HUD 逐控件满足移动端物理尺寸补偿。
- 静态参考覆盖已采样设备和状态；新增设备、系统 UI 变化通过离线补采样更新。最终报告分别注明静态检查、同步、模板和运行验证状态。
