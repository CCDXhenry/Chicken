# 烤鸡农场项目实现步骤方案

方案日期：2026-11-10。当前基线见[项目进度](烤鸡农场-项目进度.md)，需求和正式数值以[游戏功能说明](烤鸡农场-游戏功能说明.md)为准。

## 1. 实施目标与范围

在已有模块化经营 Demo 上完成新版个人农场：每位玩家独立生产、孵化、击杀、按重量拾取、逐份交货、服务员打包售卖和升级，支持四种品质、五阶成长与经营存档。

复用现有双端入口、业务子模块、NetMsg、UIManager、翻译和生命周期工具。只编辑本地脚本，沿用 Script Sync；持久化模型和 UI 在 Studio Edit 维护，所有 UI 从 `ReplicatedStorage.UI` 模板克隆。Core 沿用已有接口。本文列出的新增模块、字段和模板均为拟议实现，不代表当前已经存在。

本轮范围以 Demo 功能说明为边界。功能中的付费秒孵消耗金币，不引入 Robux 商品。图鉴、任务、宠物、离线收益和额外商业化不纳入本方案。

S8 的最小提示和操作入口应随各阶段交付，不能等到最后才具备测试入口。S1 即定义持久化字段，S7 负责最终落盘与恢复收敛。这里没有承诺日历工期；在 S2 验证地块和归属方案后，再依据实际投入、场景资产工作量和存档失败测试结果排期。

1. 以当前工作区为实现基线，列出新增/修改/删除的业务脚本、工具与资产。当前有大量未提交迁移，不能仅从最近一次 Git 提交恢复当前成果。
2. 将需求文档的 Place ID 与当前开发场景 `134743372234687` 的差异写入实施记录；核对 GameConfig 的正式/测试目标，修改前确定其真实业务含义。
3. 记录正式 UI 和场景模板的位置与备份，保留现有 RBXM、SVN 元数据和 Core 依赖。
4. 区分旧版玩法回归与新版验收：保留旧用例作为迁移参考，给新版用例另列预期，不把 6 份鸡筐等旧断言长期留作新版门禁。
5. 核对 `Tools/check-strict.ps1` 的分析环境；记录现有警告与工具缺失。后续每阶段仅对相关改动及受影响链路做必要检查。

完成标准：能说明“当前使用哪个场景、哪些是当前入口、哪些改动来自此前工作、哪些旧用例即将替换”。本阶段不清理真实存档，不自行提交、推送或发布。

## 4. S1：先固定数据契约

### 4.1 配置组织

在现有 `RoastChickenCatalog`、`FarmConfig` 上扩展；若表过大再拆 Shared 纯配置模块。所有正式参数只有一个来源。

- 物种表：英文 speciesId、显示词条、血量、产蛋间隔、孵化时间、普通重量、普通售价、解锁费、打包基础耗时。
- 品质表：英文 qualityId、概率、血量/重量/售价/孵化/打包倍率、外观配置。
- 武器表：阶位、射程、作用模式、目标上限、射界、基础伤害、强化增量、购买及强化费用。
- 拾取与鸡筐表：范围、方向条件、件数上限、承重与升级费。
- 餐厅表：等级、服务员数量、单人速度倍率、升级费。

将现有 `variant` 的物种含义显式区分为 speciesId 和 qualityId，不能把品质混入旧数字索引。校验概率总和为 1、五阶表齐全、费用边界正确，所有状态和资源标识使用英文。

### 4.2 拟议运行态与持久化字段

| 对象 | 最小字段 | 生命周期 |
|---|---|---|
| 个人农场 | farmId、ownerUserId、plotId、局部坐标原点、生产计时、实体集合 | 当前会话；plotId 不必成为永久地块绑定 |
| 玩家经营进度 | cash、unlockedSpecies、selectedSpeciesId、ownedWeapons、weaponLevels、equippedWeaponTier、collectTier、basketTier、restaurantLevel | 持久化 |
| 蛋/动物 | entityId、farmId、ownerUserId、speciesId、qualityId；蛋含飞行/孵化状态，动物含血量与受惊截止时间 | 当前会话，退出重置 |
| 地面熟食 | itemId、归属、speciesId、qualityId、重量、售价、expiresAt | 当前会话，75 秒过期 |
| 筐内货物 | itemId、speciesId、qualityId、weightKg、saleValue、必要配置版本信息 | 持久化，停止地面过期 |
| 后厨货物 | 同一 itemId、FIFO 顺序、Waiting/Processing 状态；处理中含剩余秒数、服务速度/耗时快照 | 持久化，离线暂停 |
| 会话控制 | 数据加载状态、会话标识、保存版本、脏状态、退出冻结标识 | 用于防止旧会话覆盖和退出后继续经营 |

上述字段为建议契约。重量与售价可采用生成时快照；具体保存哪些值、配置更新如何兼容，须在此阶段统一。不能通过客户端传入售价或重量。存档 Map 使用 string key，运行态 Instance、Player、连接与 os.clock 绝对值不进入存档。

### 4.3 货物状态与协议

货物流转保持同一个 itemId：`Ground → Basket → Waiting → Processing → Settled`。每次迁移只允许从预期前态成功一次；完成结算后金币增加与货物移除属于同一经营数据变更。

扩展 NetMsg 支持指定物种、装备、强化、蛋加速、金币秒孵、切换确认。请求使用受限字段与明确返回结果；服务端从 Player 查找自家农场，验证实体仍存在、归属、距离、状态、余额和冷却。确认行为绑定当前目标和状态，不能复用旧确认操作新蛋或清理新一批实体。

完成标准：配置与类型覆盖新版全部字段；有默认档和迁移输入样例；所有物品有稳定身份；保存、加载、退出和结算顺序已确定。此时先设计档结构，不能宣称保存已通过。

## 5. S2：建立个人农场和最小闭环

主要落点：`ServerGameInfo`、`ServerFarmTypes`、农场主管理器、SceneTool、Egg/Animal/Combat/Inventory/Upgrade/Restaurant。

1. 将单个 farmInfo 改为按玩家/农场管理的会话集合，每个 FarmContext 只访问自家实体、餐厅和升级状态。玩家资料加载成功后才开放经营动作。
2. 在 Studio Edit 准备可复用地块模板和地块锚点，分配、回收并绑定主人。将当前落蛋区和动物游荡的世界坐标假设改为地块局部坐标转换。
3. 明确地块不足时的等待/提示行为，避免分配同一地块给两个玩家。场内计数、生产计时和餐厅调度各自独立。
4. 临时先开放 T1 普通品质，使用新版初始血量 2、伤害 2、12 kg 鸡筐和金币 0。保留可工作的简版交货/售卖通路，S6 再替换为正式服务员调度。
5. 每个动作和目标查询都限制在本人 FarmContext；跨地块请求直接拒绝。离开先冻结业务并保留保存快照，再销毁实体、连接、标牌及回收地块。

完成标准：两名玩家各自首卖入账 10，另一人金币不变；不能处理对方蛋、动物、掉落、升级和交货；28 实体上限互不影响；退出后地块可安全复用。此阶段证明个人循环与隔离，餐厅正式时序留到 S6。

## 6. S3：物种、品质和免费切换

1. 将五阶物种参数替换为需求第 2.1 节，保持从 T1 到 T5 顺序解锁；已解锁物种可免费选择。
2. 每颗蛋只抽一次品质，沿孵化、击倒、地面、鸡筐、后厨和售款传递。临时测试入口可以指定品质，发布配置中关闭该入口。
3. 血量、重量、售价、孵化和打包耗时分别应用各自倍率；巨型视觉缩放 2.5 倍不改变 4 倍重量/血量的规则。
4. 有蛋或动物时显示清理确认；取消无变化。确认时仅清理本农场蛋/动物，保留地面熟食、鸡筐和后厨。清除相关引用和锁定目标，生产时间重设为“当前时刻 + 新物种间隔”。
5. 动物游荡约 4 studs/s，8 studs 内触发约 9 studs/s、1.2 秒受惊状态；受惊持续与再次触发边界用明确计时控制。
6. 品质标签、黄金发光、彩虹流光及巨型光环使用统一表现入口，所有临时动画随实体释放。

完成标准：黄金兔固定为 12 HP、6 kg、500 金币；品质不会在孵化或入库时重抽；28 个高阶实体仍可确认切回 T1 并在完整间隔后产蛋；品质概率用固定随机源统计，倍率用指定品质确定性验收。

## 7. S4：装备、强化和重量拾取

1. 购买武器只依赖拥有前阶，强化等级绑定具体武器；购买新阶从 Lv.1 起，保留已购武器各自等级。升级请求在同一次状态更新中验证和扣费。
2. 电击冷却 0.35 秒。首目标按准心附近、射程和射界选择；确定客户端瞄准方向如何传递后，在服务端校验有限向量和有效距离，伤害仍由服务端计算。
3. T1 命中后停止；T2 每跳从当前目标找最近有效目标，最多 3 个副目标且本发不重复；T3–T5 对扇区目标按距离分配同一发总伤害。首目标未倒下时，剩余伤害不转移。
4. 拾取冷却 0.35 秒，候选按距离排序；逐件判断承重，超重项跳过，成功件数达到工具上限才停止。T2 使用前方 100°，其余按配置。
5. 鸡筐改为总重量判断，独立逐阶购买至 972 kg；总重通过货物求和或受控更新维护，避免 UI 投影与服务端状态分叉。
6. 提示分别覆盖“单件超过空筐容量”“本趟剩余不足”“没有目标”；升级物种前展示普通/黄金所需发数以及四品质单件能否装下。

完成标准：T2 Lv.3 对两只 6 HP 普通兔分配 6+6；T3 扇区共享伤害；单体不穿透。12 kg 筐可装巨型兔肉 12 kg，装不下普通牛排 27 kg；36 kg 筐可装三份巨型兔肉。并发请求不重复拾取或重复扣费。

## 8. S5：孵化加速与金币秒孵

1. 从已落地、未孵化的自家蛋中选择近距离有效目标；飞行中不显示可操作状态。
2. 键盘 F 和触屏支持按下及长按重复请求，服务端以 0.75 秒冷却为准，每次免费减 1 秒，最低到 0；松手、切目标、失焦、关闭面板和销毁时停止任务。
3. 蛋面板展示该物种秒孵价格 5/25/125/625/3,125 金币，所有品质同价。确认时重新校验蛋状态、归属、距离、余额和目标绑定。
4. 通过单一孵化提交入口协调自然到时、免费加速和金币秒孵；一次状态转换只生成一只动物。校验通过且成功完成孵化转换时才扣款，失败不扣。

完成标准：连续请求不能绕过冷却；黄金兔只扣 25；自然孵化与确认同帧不重复产动物；余额不足、过期目标、对方蛋或已孵化蛋不扣款。触屏长按在释放后不会继续操作。

## 9. S6：逐份卸货和个人餐厅

1. 仅本人黄色交货区启动卸货，按 0.15 秒/份从 Basket 移入 Waiting；离开立刻暂停计时，重进继续待卸货物。规定首次入区后 0.15 秒卸第一份，用时间戳测试验证。
2. 入库移除地面过期语义，后厨无玩家可见容量上限。数据队列与展示模型解耦，只显示有限代表物件，避免每份库存都生成实体。
3. 服务员空闲时按 FIFO 取一份货并占用该 itemId，计算 `物种基础耗时 × 品质倍率 ÷ 接单速度倍率`；处理中保存剩余时间和接单快照。
4. 餐厅按 150/750/3,750/18,750 逐级升级；Lv.4 新增第二服务员，Lv.5 加速。新空闲工位可立即接单，旧订单继续原耗时。
5. 完成即结算给主人，顾客走路、排队和动画不能拖延收益。沿用现有顾客表现时，将其从经济状态机中解耦。
6. 等待件数、处理中件数和预计售款分别计算；预计售款包括后厨未结算货物，不重复计入已到账金币。

完成标准：逐份入库与离区暂停可观察；超过旧 24 份仍可入库；Lv.4 双工位并行；升级不追溯加速旧单；每份只触发一次售卖和入账。

## 10. S7：经营存档、恢复和结算安全

主要落点：GameConfig 默认值/类型、ServerGameInfo 初始化与序列化、版本迁移工具、ServerGameManager 加载/保存/退出，以及业务状态变更入口。

1. 增加经营存档版本，兼容没有 farm 字段的旧档，保留原设置、登录统计等通用资料。默认获得 T1 和 0 金币，不从上一个玩家会话残留生成进度。
2. 所有经营变更标脏；自动保存和退出保存覆盖金币、解锁/装备/强化、鸡筐和后厨。加载失败沿用真实服务错误处理，不创建空档覆盖已有数据。
3. 加载完成前禁止产蛋和购买；退出时冻结经营动作与结算，形成完整快照，完成保存处理后再移除状态。现有农场独立监听 PlayerRemoving，必须协调顺序，不能依赖事件连接先后保证数据存在。
4. 后厨存 remainingSeconds，重进从此值继续；离线不扣时间、不产蛋。当前会话的蛋、动物和地面熟食不恢复。
5. 金币与待结算货物放在同一个玩家经营快照中，以同一版本写入。结算一次同时增加 cash、移除货物并更新状态；保存重试复用快照，不重跑结算逻辑。
6. 评估现有 SafeSet 是否足以防止旧会话覆盖。为经营数据设计带会话/版本校验的条件更新或已有可靠会话保护接入；优先在业务层新增封装，避免无依据改动共享 Core。不能仅加 settled 布尔值就宣称跨服务器安全。
7. 定义保存失败、服务器关闭和重试策略；快照创建之后的新修改不能被旧保存成功回调错误清除脏标记。历史结算信息若需保留应设边界，避免无限追加账本。

完成标准：旧档迁移可重复安全执行；鸡筐、等待池和处理中的货物重进保持；停在打包最后时刻退出不会重复入账；重复保存、乱序保存、旧会话回写和服务失败有注入测试。需明确：幂等结算与崩溃前尚未保存的进度回退是两个问题，验收记录写清保存频率和实际恢复边界，不宣称未经验证的零丢失。

## 11. S8：界面、标牌与表现收敛

保留 Studio 模板为唯一结构与静态样式来源，在 Edit 中扩展以下拟议模板，再编写绑定代码：

| 模板/界面 | 必要信息与交互 |
|---|---|
| HUD | 金币、当前/最大 kg、武器阶位/Lv/伤害、等待/打包件数、预计售款 |
| 升级面板 | 物种、武器、强化、拾取、鸡筐、餐厅各自进度；当前值、购买后值与价格 |
| 物种选择和清理确认 | 已解锁列表、装备风险提示、清理范围与取消路径 |
| 蛋交互面板 | 品质、剩余孵化、免费加速、金币秒孵价格与确认 |
| 桌面/触屏操作变体 | Q/E/F 提示与触屏按钮，孵化长按状态和取消处理 |
