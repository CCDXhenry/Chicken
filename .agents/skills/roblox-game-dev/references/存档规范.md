# 存档规范

- 玩家存档最终会经过 JSON 序列化；JSON object 的 key 只能是 string。
- 所有需要持久化的 Map 字段必须使用 string key 定义、读写和同步，例如 `{ [string]: boolean }`。
- 从数值 id 访问存档 Map 时，必须先 `tostring(id)`；禁止在存档结构中依赖 `{ [number]: ... }`，否则保存/读取后 key 类型会漂移。
- 仅运行期临时 Map 可以使用 number key；写入 `PlayerSaveInfo`、DataStore、跨端同步存档结构前必须转换为 string key。
- 当存档数据需要按 id 快速访问，但又受 JSON key 类型限制影响时，可以将持久化结构设计为数组/List，例如 `{ { id = 1001, ... }, ... }`。
- 运行期加载后由数据层或初始化逻辑构建临时 Map，例如 `{ [number]: SaveItem }`，用于查询、校验和逻辑计算。
- 写回 `PlayerSaveInfo`、DataStore 或跨端同步前，以 List 或 string-key Map 作为最终持久化结构，避免 number-key Map 直接进入存档。
